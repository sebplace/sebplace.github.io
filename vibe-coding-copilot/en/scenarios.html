🎓 Teacher
Copilot ChatGitHub PagesCopilot Spaces

Live in class, zero install, and build something visible before the session ends.

A teacher has a course outline, wants a revision quiz and one practical exercise page, and does not want to install a full toolchain just to test the idea.

What happens

  1. Open github.com/copilot in the browser and paste the outline.
  2. Ask Copilot Chat for a first static version you can publish on GitHub Pages.
  3. Once it works, create a Copilot Space called “My syllabus” with the slides, readings, and glossary so future answers stay grounded in that course.
Copilot
I teach first-year microbiology. Build a GitHub Pages-friendly mini-site with one index.html, one style.css, and one script.js. Include 6 multiple-choice revision questions, one short case exercise, instant feedback, and a reset button. Keep the language student-friendly.
Here is a starter version with the three files, a clean layout, and the first six questions scaffolded. I also added comments so you can swap in your own course topics before publishing.

Concrete outcome

  • A working revision page in a repository
  • A GitHub Pages URL you can share the same day
  • A reusable Space for the next assignment or FAQ

Why it lands

The teacher feels the shift immediately: Copilot is not “talking about AI”; it is shipping a real teaching artefact in public view.

🧑‍🎓 Student
Copilot StudentAgent modeCopilot code review

Turn a final-year project idea into a branch-by-branch working app instead of a vague concept note.

A student team has a project brief, limited time, and wants to move from idea to MVP while still learning what the code does.

What happens

  1. Use the free Copilot Student entitlement in VS Code.
  2. Ask Agent mode to scaffold the MVP one branch at a time instead of making a giant opaque jump.
  3. Before submission, run Copilot code review on the pull requests so the team gets specific improvement notes.
Copilot
Agent mode: build a minimum viable lab-equipment booking app for a final-year project. Start with a landing page, request form, admin list, README, and one feature branch at a time. Explain each major change before applying it.
I can start with a repository plan, scaffold the first branch, and then open reviewable changes for the booking form and admin view separately so you keep the project understandable.

Concrete outcome

  • A working MVP rather than a slide deck only
  • A clearer commit and branch history for supervisors
  • Review comments that strengthen code quality before hand-in

Why it lands

The student experience stays hands-on: Copilot accelerates the build, but the branch structure and review cycle keep the learning visible.

🖥️ IT & digital services
GitHub Copilot appParallel agentsPlan mode

Clear several internal tickets in parallel without losing control of what changes where.

An IT team has a pile of small tickets — restyling a service page, migrating a script, improving a form — and wants speed without chaos.

What happens

  1. Launch the GitHub Copilot app and open several agent sessions in parallel.
  2. Keep the sessions in Plan mode so the team reviews the plan and the diffs before execution.
  3. Use the native GitHub integration to move each accepted change into the usual branch / PR / CI flow.
Copilot
Create three Plan-mode sessions: 1) migrate this CSV cleanup script to Python, 2) refresh the staff directory front page, 3) add structured logging to the room-booking service. Keep each task in its own worktree and show the plan before any edits.
I created separate plans for the three tickets, each isolated in its own session and branch. Review the diffs and approve only the pieces you want to ship this week.

Concrete outcome

  • Three parallel workstreams instead of one blocked queue
  • Reviewable diffs per ticket
  • A faster backlog rhythm with human approval still in the loop

Why it lands

This is where agent-driven development feels operationally useful rather than theatrical: parallel, isolated, and reviewable.

🤝 HR
Copilot SpacesCopilot Chat

Build a grounded internal assistant without hand-coding a backend.

HR keeps answering the same onboarding, leave, and contract-template questions, but wants answers tied to the real policy documents.

What happens

  1. Create one Space that contains the canonical HR material.
  2. Use Copilot Chat against that Space to draft answers and a simple FAQ page.
  3. Review, adjust tone, then publish the approved version as an internal reference page.
Copilot
Create a Space called HR policies using these onboarding guides, leave procedures, contract templates, and FAQ notes. Draft a staff-facing question page that answers the top 12 recurring questions and clearly cites the policy source for each answer.
I grouped the source material, drafted answer patterns grounded in the uploaded documents, and produced a clean FAQ-style page that HR can review before publishing internally.

Concrete outcome

  • A grounded FAQ instead of another overflowing mailbox
  • Faster onboarding answers for staff
  • A reusable Space that improves future HR prompts

Why it lands

The key win is trust: people get answers from the institution’s own documents, not generic web prose.

🧭 Leadership
Custom agentsCopilot cloud agentAutomations

Turn weekly KPI chasing into a scheduled, reviewable synthesis flow.

A dean or department head wants one concise weekly picture across several teams without manually collating every update.

What happens

  1. Create a custom agent persona for the reporting style you want.
  2. Schedule a Copilot cloud agent automation to run every week.
  3. Review the PR, not a mystery email attachment, before the summary is circulated.
Copilot
In .github/agents/reporting.md, define an agent that reads the KPI files in /finance, /student-success, /research, and /operations, then writes a weekly-summary.md draft with wins, risks, and open questions. Schedule it every Friday afternoon and open a PR instead of editing main directly.
I can use the custom agent instructions, pull the source files together, and raise a reviewable PR with the proposed weekly summary so leadership approves the narrative before it is shared.

Concrete outcome

  • A repeatable weekly reporting ritual
  • One PR that leadership can comment on
  • Less coordinator time spent copy-pasting status updates

Why it lands

Leadership gets the speed of automation while keeping the institutional review checkpoint where it belongs: before publication.

💶 Finance
Prompt filesCopilot ChatAI credits

Turn a monthly export into a dashboard in minutes and keep the AI-cost story measurable.

Finance receives a recurring Excel or CSV export and wants a lightweight dashboard instead of rebuilding the same spreadsheet views every month.

What happens

  1. Create one shared prompt file for the recurring finance workflow.
  2. Feed the current export into the template instead of re-explaining the task every month.
  3. Track the run inside your normal organisational AI-credit pool rather than guessing at a flat mystery cost.
Copilot
Use .github/prompts/budget-dashboard.prompt.md with inputs [export_file] and [month]. Transform the attached budget export into a static dashboard with variance cards, a sortable table, and overspend flags. Keep calculations visible in code and explain the estimated AI-credit usage for this run.
I drafted the prompt-file template, converted the export into a one-page dashboard, and kept the formulas visible so the team can audit both the numbers and the build process.

Concrete outcome

  • A reusable dashboard workflow
  • Visible calculations in code
  • A concrete finance story for why pooled AI credits are easier to govern than guesswork

Why it lands

Finance does not have to love hype to see the value: the result is faster reporting with a clearer cost model.

🔬 Research
MCP serversCopilot ChatPython / R script generation

Ask a dataset a plain-language question and still receive the script behind the answer.

Researchers want faster access to trusted data, but they also need reproducibility and an inspectable analysis path.

What happens

  1. Connect an approved MCP server to the relevant dataset.
  2. Ask the question in Copilot Chat instead of manually stitching together the first query.
  3. Take the generated Python or R script as the reproducible artefact for review, reuse, or publication support.
Copilot
Using the approved retention-data MCP server, compare retention for cohorts 2022 to 2025 by faculty. Then generate the Python notebook that reproduces the chart and add comments explaining every transformation step.
I can query the connected dataset, summarise the comparison in plain language, and generate the notebook so the research team can rerun or adapt the method.

Concrete outcome

  • A faster path from question to first analysis
  • A script the team can inspect and rerun
  • A grounded workflow that respects research traceability

Why it lands

This keeps the convenience of natural language without giving up the reproducibility researchers need.

📚 Library / campus services
Agent modeGitHub PagesGitHub Campus Program

Let a non-developer service team ship a useful mini-app instead of waiting for a full system replacement.

Library or campus staff need a simple room-booking or inventory-tracking tool for one service point and want something practical this semester.

What happens

  1. Use Agent mode to scaffold the first version quickly.
  2. Host the app on GitHub Pages using the institution’s GitHub platform footprint.
  3. Keep the content editable enough that library or campus staff can own the page after launch.
Copilot
Build a static room-booking prototype for the library: date selector, room cards, booked/free status using mock data, accessibility notes, and a GitHub Pages deployment workflow. Keep the structure easy for non-developers to edit later.
I scaffolded a small static app, added accessible room cards and a deploy workflow, and kept the content files simple so the service team can maintain the page after the first launch.

Concrete outcome

  • A working service prototype instead of a long waiting list
  • Free static hosting on GitHub Pages
  • A concrete demonstration of what the Campus Program platform can enable

Why it lands

The library team sees immediate value because the result is a usable service page, not an abstract AI pilot.
